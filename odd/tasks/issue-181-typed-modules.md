## Objective, problem, and boundaries

Make the archetype's own ESM implementation modules typed TypeScript `.mts`, eliminate tracked and archetype-generated `.mjs` modules, and prevent future untyped JavaScript implementation modules from entering the archetype. Today the extension and generated-asset boundaries are not enforced; a new `.mjs` file could bypass the typed-source convention, while an indiscriminate extension ban would incorrectly reject host-required `.ts` integrations or compiled output.

In scope: tracked-module and payload inventories; `.mjs` to `.mts` migration where applicable; import and runtime specifiers; compiler/build/test/CLI execution; ownership and payload lock; startup/hooks, workflow and CI consumers; documentation; deterministic path-reporting policy for both source and fresh generated support assets; focused and end-to-end offline regressions.

Out of scope: new runtime behavior, provider/CI recipe semantics, unrelated TypeScript refactors, rewriting historical task evidence, migrating an initialized user's application code, publication, hosted workflow dispatch, and unrelated remote mutations. The earlier first-child implementation slice was local-only; its PR delivery is recorded below. Keep existing `.ts` host integrations (`hooks/opencode/factory-start.ts`, `hooks/pi/factory-start.ts`, and the generated OpenCode plugin) where their host requires `.ts`. Existing creator `src/*.ts` is CommonJS under `package.json`/`tsconfig.json`; decide its treatment by actual module contract, not a blanket filename replacement.
