# ODD feature task: Agent Foundry v0.1.2

## Objective

Deliver the next-version backlog for `v0.1.2` as independently reviewable work units, preserving the published `v0.1.0` release contract and keeping unfinished provider and typed-module work explicit.

## Scope

In scope:

- #241: resilient post-publish npm registry readback with bounded retry/backoff and regression coverage.
- #240a: deterministic changelog/release-note automation as an independent slice.
- #240b: local hosted-journey contract/configuration repair, without claiming a hosted green run.
- #181: one bounded typed-module migration slice from the existing ledger, with tests and payload/ownership evidence; no whole-tree completion claim until the remaining migrations are done.
- #178: the next safe provider-persistence adapter unit from the existing contract, using injected offline capabilities only.

Deferred from this feature:

- #240 hosted journey proof remains blocked on its provisioning and scheduled-version failures, even after any local contract repair.
- #179 harness lifecycle wiring depends on a completed callable provider boundary.
- #180 provider matrix closure depends on #178 and #179.
- #177 issue-wide closeout still requires provider-confirmed handoff/readback.
- #1 and #3 remain `v0.2.0` work and live organization provisioning needs separate authorization.

## Constraints

- Repository and artifact language: English; conversation language: Spanish.
- Ordinary functional testing is active; strict RED/GREEN TDD is not enabled for the inherited #177/#178/#181 ledgers.
- Work in isolated worktrees for concurrent implementation. One writer per work unit; integrate and verify sequentially in this feature worktree.
- No live provider mutation, publication, issue mutation, merge, or release action without the exact destination/operation/credential authorization required by the repository contract.
- Keep tests and documentation with the behavior they verify. Generated payload locks must be rebuilt only after final source inputs for a work unit.
- Each task closes with a Conventional Commit and records its exact checks, runtime scenario or justified N/A, rollback boundary, and remaining blockers.
