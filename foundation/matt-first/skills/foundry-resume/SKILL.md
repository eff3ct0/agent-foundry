# Cold resume

Explicit selection or a covering delegation must name the unit and permitted effects. This procedure recovers context; it is not a session-reset API, scheduler or permission to launch/claim work. A genuinely new session must have demonstrable independent identity/context/lineage where required; a subagent, fork, resumed transcript or forget prompt does not establish isolation.

## Bounded reading order

1. Run the accepted passive startup path, read the repository integration envelope, applicable local rules and accepted binding/control context. Git provenance identifies content and readiness-record pointers, not native task state. A local installer ledger is ownership/recovery evidence, not required task authority.
2. Fresh-read the exact provider/repository/project/task identity, native state, owner, parent/blockers and explicitly identified canonical confirmed checkpoint. An arbitrary latest comment is not automatically canonical. Do not start from stale local task lists or parent conversation. Silence does not permit takeover; require a confirmed transfer when needed.
3. Load only relevant linked canonical specification/decision constraints for the next action. Reconcile the task definition, confirmed packet and actual work; changed substantive intent needs authorized reconciliation, not whichever prose is newest.
4. Retrieve every necessary exact artifact/WIP/evidence reference. Verify actual identity, availability and required integration in this working revision. A closed predecessor, named branch or commit mention is insufficient. Missing local-only bytes mean exact recovery/transfer is unavailable; do not reconstruct and call it identical resumption.
5. Inspect subsequent native history and actual artifacts after the checkpoint. Reconcile possibly completed external/filesystem effects on their exact targets before retry; record partial or unknown outcomes honestly. Do not replay an old next-action instruction blindly.
6. Revalidate owner/dependencies, current authority, workspace/conflicts, selected route/access, artifact readiness and required tooling/evidence. Source, host, adapter, binding, rule or workspace changes invalidate affected observations, not unrelated proof. Previous-host readiness is not portable credentials.

## Next action and permitted effects

Identify the valid owner, accepted scope, completed work, exact available artifacts/evidence, missing gates and **one exact next authorized action**. A read-only discovery check stops here; it does not manufacture a write or start planning/implementation. Initial empty-project discovery can propose planning, but cannot claim recovery of nonexistent WIP.

If actual continuation is authorized, perform only that action under the relevant indexed procedure and current gates. Claims/transfers, comments, relations and status/checkpoint/completion each need provider-native confirmation plus a fresh matching exact-target readback. Context loading alone is not evidence that work resumed. At the next recoverable milestone use foundry-checkpoint on the same task; preserve exact artifact availability and activity to resume.

Missing binding/access/resource/artifact, contradictory authority, malformed/mismatched readback or failed required check stops only the affected action. Name the exact missing fact, operation/target, owner, required evidence/permission and safe next action; never invent success, a human answer, approval or local fallback tracker. Inspect an uncertain mutation's target before another attempt. Continue independent already-authorized work only when shared-state safety is established; otherwise pause.

## Completion evidence

The cold reader can identify current native owner/state/dependencies, scope, exact next action and actual artifacts without old chat/temp or original local ledger. Report the observed host/content/access context and limits. Claim resumed work only with an authorized action and observed result; claim transfer-ready only with all required exact bytes retrievable on the next authorized machine. Neither this procedure nor a confirmed packet grants merge, deployment, migration/deletion, publication, global configuration or automatic launch.
